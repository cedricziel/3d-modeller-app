# CAD 12: Export Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The rebuilt model leaves the app as STEP (with assembly structure, names and colours), binary STL and 3MF, through File ▸ Export…, the `export` tool and `cadbench`'s `final.step`, and every writer is checked by reading its file back.

**Architecture:** `CADModel` plans an export without the kernel: it turns a target (document, part, body, instance) and a `RebuildResult` into an `ExportScene` of products (a part's bodies, unmoved, with a name and a colour) and occurrences (a product placed by an instance's solved transform). `ModelGeometry` gains `export`, which swaps the scene's body keys for kernel bodies and either hands the scene to the kernel's STEP writer (XDE document via OCCTSwift) or tessellates each body at the export tolerance and writes STL or 3MF in pure Swift. 3MF is a stored (uncompressed) zip written by a small `ZipArchive` with its own CRC-32. `CADAssistantTools` adds `CADSession.export` and the `export` tool, which writes only inside a directory the host grants. The app adds File ▸ Export… (a sheet for format and scope, then `NSSavePanel`), and `cadbench` writes `final.step` per run.

**Tech Stack:** Swift 6 (tools 6.1), Swift Testing, OCCTSwift 3.0.0 (`Document`, `Exporter.writeSTEPAssembly`, `Shape.loadSTEP`, `Document.loadSTEP`), Foundation (`XMLParser` in tests), SwiftUI/AppKit (`NSSavePanel`). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-09-26-cad-roadmap-design.md`: "Export", "Agent tools" (`export`), "Benchmark", PR-stack row 12. Previous layer: `docs/superpowers/plans/2026-09-26-cad-11-motion.md`.

## Global Constraints

- macOS 26, Apple Silicon only, Swift 6 strict concurrency. Use `xcrun swift`, never bare `swift`.
- Only `CADKernel` imports OCCTSwift. `CADModel` stays pure Swift. Every OCCT call runs inside `OCCTSerial.withLock {}`.
- No C++ exception may reach Swift. Every failure is a typed error.
- Millimetres everywhere: the STEP length unit is mm, 3MF declares `unit="millimeter"`, STL is written in mm.
- The document format stays 1; export adds nothing to the document.
- Tests use Swift Testing, never block a cooperative thread, and hoist long expressions out of `#expect`.
- Semantic commits, one concern each, no "and" in the subject, no co-author lines. Comments only state a non-obvious why.

## Rulings

- **Ruling: STEP is written as AP214 (`AUTOMOTIVE_DESIGN`), not AP242.** OCCTSwift 3.0.0's XDE writer (`Document.writeSTEP`, `Exporter.writeSTEPAssembly`) exposes no schema switch, and the other OCCTSwift STEP writers pin `write.step.schema` to AP214. AP214 carries everything this layer writes (product structure, names, colours, mm); AP242's additions (PMI, GD&T) are not produced by the model. Cost if wrong: a consumer that requires AP242 must re-save; switching needs one bridge hook in OCCTSwift.
- **Ruling: the scene's shape.** A product is a part's bodies (all of them, or the one body an instance or a body target selects) at the part's own coordinates, named after the part (`Plate`, or `Plate/Body2` for a single body of a multi-body part). Bodies inside a multi-body product are named `Body1`, `Body2`, …. Occurrences name the instance and carry its solved transform. Products are shared: two instances of the same part and body selection reference one product. Cost if wrong: none.
- **Ruling: what each target exports.** Document: the assembly when it has at least one placed instance, else every part as a free product at the origin. Part: that part's bodies. Body: that one body. Instance: its product placed where the assembly puts it. Failed instances and bodies the kernel did not build are left out and listed in the summary as skipped; when nothing is left the export fails with the reasons. Cost if wrong: an export silently misses a broken instance; the summary names it.
- **Ruling: colours come from the render palette.** The document stores no colours; each product gets the next colour of the palette `render_views` uses (moved to `CADModel` as `ExportPalette`), so an exported assembly is coloured like its renders. STEP sets the colour on the product's shapes; 3MF uses `basematerials`. Cost if wrong: none.
- **Ruling: STL and 3MF are written in Swift from the kernel's tessellation.** The kernel tessellates each body at the export tolerance (`GeometryKernel.mesh(of:tolerance:)`, default 0.01 mm linear deflection); `STLWriter` writes binary STL (every occurrence's bodies moved into place, one file) and `ThreeMFWriter` writes one mesh object per product body, a components object per multi-body product, and one build item per occurrence with its transform. OCCT's own STL writer is not used, so STL and 3MF share one tessellation and are testable with the fake kernel. Cost if wrong: none; OCCT's writer meshes the same way.
- **Ruling: 3MF's zip is stored, not deflated.** `ZipArchive` writes method 0 entries with CRC-32, which OPC and every 3MF reader accept. Files are bigger than deflated ones. Cost if wrong: large meshes give large files; `Compression`'s raw deflate can be added to `ZipArchive` later.
- **Ruling: the `export` tool writes only inside a directory the host grants** (`CADSession.exportDirectory`). The path must be relative, must not contain `..`, `~` or a leading `/`, and must resolve (after resolving symlinks of its existing parent) inside that directory; missing subfolders are created; the format's extension is appended when missing and refused when it names another format; an existing file is refused unless `overwrite: true`. With no granted directory the tool refuses. The app grants `~/Downloads/3D Modeller Exports` (sandbox entitlement `com.apple.security.files.downloads.read-write`); `cadbench` grants the run's result folder. Cost if wrong: agents in the app cannot write next to the document; File ▸ Export… can write anywhere the user picks.
- **Ruling: File ▸ Export… uses a sheet (format, scope, tolerance for mesh formats) and then `NSSavePanel`,** because the save panel alone cannot pick a scope. It runs the same `CADSession.export` as the tool. Cost if wrong: none.
- **Ruling: `cadbench` writes `final.step` per run** by exporting the final document with the same code; an export failure is recorded in `run.json` as `exportError` and does not fail the run. The optional `exportRoundTrip` check is not added: the kernel round trip is covered by tests and `final.step` is inspectable. Cost if wrong: an export regression shows only as a missing file in results.

## Execution rulings

- **Ruling (execution): STL, 3MF and STEP readers ship in the libraries** (`STLReader`, `ThreeMFReader`, `ZipArchive.entries`, `OCCTGeometryKernel.inspectSTEP`, `Kernel.readSTEP`) so every package's tests check files with one reader; they read only what the writers write (stored zip entries). Cost if wrong: none.
- **Ruling (execution): the STEP write always calls `updateAssemblies()`**, also without occurrences, because a multi-body product is itself a small assembly and is empty in the file otherwise. Cost if wrong: none.
- **Ruling (execution): a product is identified by its part and body selection, not its name**, so two parts with the same name stay two products (review). Cost if wrong: none.
- **Ruling (execution): 3MF meshes are welded by exact vertex position** before writing, and triangles that collapse are dropped (review: OCCT meshes each face separately, so shared edges were open). Cost if wrong: two distinct vertices at the same float position would merge; they are the same point.
- **Ruling (execution): `cadbench` grants the export tool `<task>/run-<n>/exports/`,** and `final.step` goes through the same redaction as the other text files. Cost if wrong: none.
- **Ruling (execution): the tool's `tolerance` must be a plain number from 0.001 to 1 mm and is refused for STEP.** Cost if wrong: none.
- **Ruling (execution): File ▸ Export… sits after the import/export command group, ⇧⌘E.** Cost if wrong: none.
- Verification: `MotionIntegrationTests.freeHingeHasOneFreedom` fails on the base 1bf6623 as well (fixed in PR 11 as cec33c8); CADSessionTests' four gate tests fail under `LIBDISPATCH_COOPERATIVE_POOL_STRICT=1` by design, as in PR 11. Everything else passes, strict or not; no long-expression warnings.

## Deferred after the final review

- `ExportPath` checks the target before the rebuild and export; the write itself is not exclusive, so a file or symlink planted by another local process in between is replaced (`.atomic`) or followed (OCCT's STEP writer). Needs a temp file plus an exclusive rename.
- Intermediate folders are checked with `fileExists`, which follows symlinks; a dangling symlink subfolder fails only because `mkdir` refuses it. Use `lstat`.
- `ExportPath.resolve` creates folders before the export can fail, leaving empty folders; a file named `.step` becomes `.step.step`.
- `Kernel.readSTEP` parses the file twice and can list a colour twice.
- The export sheet computes its scopes once from `session.result`, which can be stale while a rebuild runs.
- No external 3MF validator runs in the tests; the package was checked by inspection and by `unzip -t`.

## Review Focus

1. **An assembly whose instances were moved by joints (a rotated lid).** Expected: the STEP occurrence and the 3MF build item carry the solved transform, not the document placement, so the round-tripped bounds equal the rebuild's instance bounds. Pinned in Task 4 (`solvedTransformRoundTrips`).
2. **A document where one instance failed or one body did not build.** Expected: the rest is exported and the skipped items are named; with nothing left, a typed error naming why. Pinned in Task 2 (`failedInstanceSkipped`, `nothingToExport`).
3. **Tool paths that escape the granted directory** (`../x.step`, `/tmp/x.step`, `~/x.step`, a symlinked subfolder pointing outside). Expected: refused with the rule, nothing written. Pinned in Task 5 (`pathEscapesRefused`, `symlinkEscapeRefused`).
4. **Exporting over an existing file.** Expected: refused unless `overwrite: true`; with it, replaced. Pinned in Task 5 (`existingFileRefused`).
5. **A part used by two instances.** Expected: one STEP product, two occurrences; the read-back has two solids with twice the volume. Pinned in Task 1 (`sharedProductTwoOccurrences`) and Task 4.

### Task 1: STEP in the kernel

**Produces:**

```swift
public struct STEPProduct: @unchecked Sendable {
    public var name: String
    public var bodies: [(name: String, solid: Solid)]
    public var color: SIMD3<Double>   // 0…1 RGB
}
public struct STEPOccurrence: Sendable {
    public var name: String
    public var product: Int
    public var rotation: simd_double3x3
    public var translation: SIMD3<Double>
}
public struct STEPContents: @unchecked Sendable {
    public let solids: [Solid]          // placed, in file coordinates
    public let names: [String]          // every named node, depth first
    public let colors: [SIMD3<Double>]  // every coloured node
}
extension Kernel {
    /// Occurrences empty: each product is a free shape. Otherwise one root assembly named `name` holds them.
    public static func writeSTEP(
        products: [STEPProduct], occurrences: [STEPOccurrence], name: String, to url: URL) throws
    public static func readSTEP(from url: URL) throws -> STEPContents
}
```

Writing: `Document.create()`; each product: one body → `addShape(solid.shape, makeAssembly: false)`; several → `newShapeLabel()` plus `addComponent(... matrix: identity)` per body, each body label named. Name via `document.node(at:)?.setName`, colour via `setColor`. Occurrences: `newShapeLabel()` root, `addComponent(assemblyLabelId:shapeLabelId:matrix:)` with the rotation re-orthonormalised through `simd_quatd` (row-major `r00 r01 r02 r10 … tx ty tz`), component node named; `updateAssemblies()`; `Exporter.writeSTEPAssembly`. A `-1` label or a false return throws `KernelError.operationFailed("write the STEP file")`.

Reading: `Document.loadSTEP(from:)` for names and colours (walk `rootNodes`/`children`), `Shape.loadSTEP(from:)` for the placed solids (`shape.solids`).

public enum ExportFormat: String, Sendable, CaseIterable, Codable {

    public var isMesh: Bool

public enum ExportTarget: Sendable, Hashable {
    case document, part(UUID), body(part: UUID, body: String), instance(UUID)

public enum ExportPalette { public static let colors: [(name: String, rgb: SIMD3<Double>)] }  // render_views' 8
